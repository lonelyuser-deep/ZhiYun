# 智云校遇 ZhiYun

面向在校学生的校园活动与机会信息网页原型。

- 在线体验：<https://lonelyuser-deep.github.io/ZhiYun/>
- 技术栈：原生 HTML、CSS、JavaScript；无需安装依赖或配置后端。

## 解决的问题

新生与在校学生会同时接触学校、学院和学生个人发布的比赛、讲座、招募、学习与兴趣活动。它们的来源、时间、地点、报名状态和信息完整度各不相同；用户往往需要反复比对，才能判断一条信息是否值得关注、是否仍可参与。

智云校遇聚焦“更快发现、理解和处理校园机会”：在同一信息流中保留来源与状态差异，帮助用户筛选内容、查看关键信息、保存感兴趣的机会，并允许学生发布自己的活动或招募。

## 主要使用流程

1. 打开网站后进入校园封面页，点击“进入校园”。
2. 在发现页按关键词、类型、发布来源筛选信息，并选择综合、热门或实用排序。
3. 打开详情查看时间、地点、参与条件与参与方式。
4. 绑定昵称后，可以点赞、关注、收藏或置顶信息；这些状态会在刷新后保留。
5. 在“发布信息”中提交个人活动或招募，发布结果会立即进入正常信息流。

## 核心功能

- **多来源信息浏览**：使用题目提供的模拟校园信息，区分学校、学院与学生个人发布内容，并呈现报名中、即将截止、待确认等状态。
- **定位与理解信息**：支持关键词、类型、来源筛选；详情页集中展示活动时间、地点、容量/条件和参与方式。
- **身份绑定与操作留存**：以本地昵称模拟身份绑定；收藏、点赞、关注、置顶和学生发布的数据通过浏览器 `localStorage` 保留。
- **学生自主发布**：学生可发布活动或招募，内容会进入发现页并与既有信息使用同一套浏览、筛选和详情流程。

## 自主设计的实用功能

### 信息价值排序与重点信息机制

平台为每条信息展示浏览、点赞、关注数据，并提供“综合 / 热门 / 实用”排序和手动置顶。综合排序会参考互动表现、发布来源、信息状态等信号，帮助用户优先看到更值得进一步了解的内容。

这些数据只用于降低浏览成本，**不代表平台对活动真实性或质量作出官方认证**。用户仍可以在详情中核对时间、地点、参与条件与发布来源。

### 不确定信息的显式呈现

题目中的学生个人发布信息可能存在场地或时间待确认的情况。页面会标记“待确认”状态，并在详情中保留原有的不确定性，而不是擅自补全为确定事实。

## 主动发现并处理的关键问题

同一活动可能出现补充通知，导致原始时间或地点不再准确。例如“蓝桥杯”训练营的补充通知调整了首次训练时间和场地。项目以更新后的信息展示时间与地点，并在详情中说明该条为场地调整后的补充内容，避免用户把旧通知误认为仍然有效。

同时，对于学生个人发起且关键信息尚未确认的内容，项目不将其包装成正式通知，而是保留学生来源与“待确认”标识，让开放发布与用户判断成本之间保持边界。

## 运行与部署

### 在线访问

项目已发布到 GitHub Pages：<https://lonelyuser-deep.github.io/ZhiYun/>

### 本地运行

直接用浏览器打开 `index.html`，或在项目根目录启动任意静态文件服务器后访问首页。例如：

```bash
python -m http.server 4173
```

然后访问 `http://localhost:4173/`。

## 项目结构

```text
index.html                    页面结构与入口封面
styles.css                    视觉样式、响应式布局和入口动画
app.js                        信息筛选、详情、绑定、发布与本地持久化
assets/autumn-campus-cover.png 入口封面图片
```

## 数据与边界

- 页面数据为考核题目中的模拟校园信息及其场景化呈现，不代表学校真实通知。
- 项目是无后端静态网页原型；身份绑定仅保存昵称和可选身份描述，不采集密码、证件号等敏感信息。
- 当前互动与发布数据仅保存在用户当前浏览器。迁移到微信小程序或正式产品时，应由微信授权与后端数据服务替换。

## 后续可完善方向

- 引入可信来源认证、举报和内容审核机制，进一步处理广告或推广类信息。
- 支持活动通知更新的关联与历史追踪，避免新旧通知混淆。
- 迁移到微信小程序：拆分页面组件，以微信授权替换昵称模拟绑定，并接入合规的数据服务。
